## 1. 개요

2인용 모드는 클래식 B3/S23 규칙을 그대로 쓰고, 셀에 소유자(A/B)를 붙여 두 플레이어가 영역을 다투는 승패 게임이다. 이웃 수 계산과 생존·사망 판정은 클래식 모드와 같고, 새로 태어나는 셀의 색만 추가로 정한다.

- 범위: 한 화면에서 두 사람이 번갈아 조작하는 hot-seat 방식. 네트워크 대전은 범위 밖이다.
- 클래식 모드와의 관계: 클래식 모드는 그대로 동작해야 한다(과제 요구사항). 2인용 모드는 규칙·상태·승패 판정을 교체해서 만든다.
- 표기: 예시 격자에서 `A`·`B`는 각 플레이어의 살아 있는 셀, `.`은 죽은 셀이다. 좌표는 (행, 열), 0부터 센다.
- 상태: 이 문서의 모든 결정은 초안(안)이다. 수치(배치 개수, 세대 수, 라운드 수)는 플레이 테스트 후 조정한다.

## 2. 용어와 셀 상태

셀은 `DEAD`, `A`, `B` 세 상태 중 하나다. `A`와 `B`는 모두 "살아 있음"으로 취급한다.

| 용어 | 정의 |
| --- | --- |
| 셀 상태 | `DEAD`, `A`(플레이어 A 소유 생존), `B`(플레이어 B 소유 생존) |
| 이웃 | 8방향(상하좌우 + 대각선)의 셀. 보드 밖은 항상 `DEAD`(기존 `Cell.DUMMY`와 동일) |
| 세대 | 모든 셀에 전이 규칙을 동시에 적용하는 1회. tick 1번 = 1세대 |
| 진영 | 보드를 열 기준으로 반으로 나눈 영역. A = 왼쪽 절반, B = 오른쪽 절반 |
| 라운드 | 시뮬레이션 단계 1회 + 개입 단계 1회의 묶음 |
| 선공 | 배치 단계에서 먼저 두는 플레이어 |
| 점수 | 현재 보드에 살아 있는 자기 셀의 수 |

## 3. 세대 전이 규칙

생존·사망은 색을 무시한 이웃 수로 판정하고, 탄생하는 셀만 이웃 3개 중 다수인 색을 따른다(Immigration 방식). 살아 있는 셀의 색은 죽을 때까지 바뀌지 않는다.

`n` = 살아 있는 이웃 수(`A` + `B`), `a` / `b` = 그중 `A` / `B`의 수.

| 현재 상태 | 조건 | 다음 상태 |
| --- | --- | --- |
| `A` 또는 `B` | `n` = 2 또는 3 | 같은 상태 유지(생존) |
| `A` 또는 `B` | `n` ≤ 1 또는 `n` ≥ 4 | `DEAD`(고립사·과밀사) |
| `DEAD` | `n` = 3, `a` ≥ 2 | `A` |
| `DEAD` | `n` = 3, `b` ≥ 2 | `B` |
| `DEAD` | `n` ≠ 3 | `DEAD` |

- 동률은 생기지 않는다. 탄생 조건이 `n` = 3(홀수)이라 `a`와 `b` 중 하나는 반드시 2 이상이다.
- 상대 셀도 이웃 수에 들어간다. 그래서 내 셀 옆에 상대 셀이 몰리면 내 셀이 과밀로 죽는다. 이것이 상대를 공격하는 유일한 수단이다.
- 색을 지우면 클래식 B3/S23과 완전히 같다. 같은 초기 배치라면 살아 있는 셀의 위치는 두 모드에서 항상 같고, 색만 다르다. 테스트에서 이 성질을 회귀 검증용 불변조건으로 쓸 수 있다.
- 모든 셀은 이전 세대 상태만 보고 동시에 갱신한다(기존 `figureNextState` → `transition` 2단계 구조 유지).

채택하지 않은 대안: 단색일 때만 탄생(클래식과 동작이 달라짐), 무작위 색(테스트 재현 불가), 생존 셀 전향(진동 패턴에서 색이 계속 뒤집힘).

## 4. 게임 진행

게임은 초기 배치 1회 뒤 "시뮬레이션 → 개입" 라운드를 R번 반복한다. 기본값은 N = 20, K = 20, M = 3, R = 5(총 100세대)이고, 네 값 모두 설정값으로 빼서 바꿀 수 있게 한다. 테스트에서는 작은 값을 주입한다.

1. **초기 배치**: A와 B가 1개씩 번갈아 둔다. 각자 N개를 두면 끝난다. 선공은 A이고, 패스는 없다.
2. **시뮬레이션**: K세대를 자동으로 진행한다. 이 단계에서는 배치 입력을 받지 않는다. 매 세대 끝날 때마다 종료 조건(6장)을 검사한다.
3. **개입**: 각자 배치 개수 M개를 받는다. 자기 차례에 셀 1개를 두거나 패스한다. 두 사람이 연달아 패스하면 단계가 끝나고, 쓰지 않은 개수는 사라진다. 선공과 후공은 초기 배치부터 이어서 번갈아 간다. 초기 배치의 후공이 B이므로 라운드 1 개입의 선공은 B이고, 라운드 2는 A, 라운드 3은 B다.
4. 2~3을 한 라운드로 세고, R번째 라운드의 시뮬레이션이 끝나면 개입 없이 종료 판정으로 간다.

| 단계 | 받는 입력 | 다음 단계로 넘어가는 조건 |
| --- | --- | --- |
| 초기 배치 | 현재 차례 플레이어의 셀 배치(확정 전 이동 가능) | 양쪽 모두 N개 배치 |
| 시뮬레이션 | 없음(속도 조절만 허용) | K세대 진행 → 개입 / 종료 조건 → 종료 |
| 개입 | 현재 차례 플레이어의 셀 배치(확정 전 이동 가능)·패스 | 두 사람이 연달아 패스 |
| 종료 | 없음 | — |

- 개입 단계는 모든 배치가 공개되는 수읽기 싸움이다. 상대가 셀 1개로 내 정물을 저격하면, 나는 남은 개수로 받아칠 수 있다(7장 예시 5).
- **패스 규칙을 둔 이유**: "각자 M개를 다 두면 끝"이면 마지막 수를 두는 사람이 순서로 정해지고, 그 수로 하는 저격은 받아칠 수 없다. 두 사람이 연달아 패스해야 끝나면, 저격당한 쪽은 남은 개수가 있는 한 항상 대응할 수 있다.
- 확정 저격은 상대가 배치 개수를 먼저 다 썼을 때만 가능하다. 따라서 개수를 언제 쓰고 언제 아낄지도 수읽기 요소가 된다.
- 개수가 0인 플레이어나 둘 빈칸이 없는 플레이어는 자동으로 패스한다.
- 선공 이점은 1개씩 번갈아 두기와 라운드별 선공 교대로 줄인다.
- 수동 진행 버튼(기존 메뉴의 Tick)은 시뮬레이션 단계에서만 동작하고, 한 번에 1세대씩 K에 포함해 센다.
- 단계마다 받는 입력과 다음 단계가 다르므로 State 패턴(`PlacementPhase`, `SimulationPhase`, `InterventionPhase`, `GameOverPhase`) 후보다. 패스와 배치는 Command(`PlaceCellCommand`, `PassCommand`)로 만들면 Clock 리팩토링의 Command 구조와 맞출 수 있다.

## 5. 배치 규칙과 제약

셀은 빈 칸에만 둘 수 있다. 초기 배치는 자기 진영으로 제한하고, 개입은 상대 진영을 포함해 보드 어디든 둘 수 있다.

| 규칙 | 초기 배치 | 개입 |
| --- | --- | --- |
| 배치 대상 | `DEAD` 칸만 | `DEAD` 칸만 |
| 배치 영역 | 자기 진영(A 왼쪽 절반, B 오른쪽 절반) | 제한 없음(상대 진영 포함) |
| 배치 개수 | 각자 정확히 N개 | 각자 최대 M개(패스 가능) |
| 취소 | 클릭하면 임시 배치, 다른 빈칸을 클릭하면 이동. 확정(버튼 또는 Enter)하면 차례가 넘어가고, 확정된 셀은 취소 불가 | 같음 |
| 임시 배치 없이 확정 | 거부(차례 그대로) | 같음 |
| 불가능한 클릭 | 무시하고 상태 표시줄에 이유 표시 | 같음 |

- 살아 있는 셀(자기·상대 모두) 위에는 두지 못한다. 클릭으로 상대 셀을 지우면 규칙(이웃 상호작용)으로 싸운다는 취지가 깨진다.
- "내가 둔 셀"은 확정 전의 임시 배치 1개만 뜻한다. 차례가 넘어간 뒤에도 취소할 수 있으면, 상대가 대응한 뒤 내 수를 바꿔 상대 대응을 헛수로 만들 수 있어서 수읽기가 성립하지 않는다.
- 임시 배치 없이 확정하면 거부한다. 초기 배치에는 패스가 없으므로 빈 확정으로 차례를 넘길 수 없고, 개입에서 차례를 넘기려면 패스를 쓴다.
- 개입 영역을 제한하지 않으면 셀 1개로 상대 정물을 없애는 저격이 가능해진다(예시 5). 모든 배치가 공개되고 패스 규칙(4장) 때문에 저격에는 항상 대응 기회가 있어서, 저격과 대응이 수읽기의 일부가 된다.
- 채택하지 않은 대안: 자기 셀 인접 칸만 허용(저격을 전선으로 한정), 자기 진영만 허용(개입이 수비용으로만 쓰임), 상대 셀과 접촉하는 칸 금지(저격 자체를 차단), 동시 비공개 배치(심리전이 되지만 hot-seat에서 화면을 가려야 함).

초기 배치의 마지막 수(후공 B의 N번째)는 받아칠 기회가 없다. 진영이 맞닿아 있어서, 경계 바로 건너편의 상대 셀 옆에 두는 저격이 가능하다. 이는 의도된 위험으로 둔다. 경계 근처에 두는 것은 플레이어가 감수하는 선택이고, 영향은 첫 라운드의 경계 근처로 한정된다. 대안이었던 "경계 양쪽 1열 초기 배치 금지"는 채택하지 않았다.

## 6. 종료 조건과 승패 판정

게임은 한쪽이 전멸하거나 R라운드가 끝나면 끝난다. 전멸이면 남은 쪽이, 라운드 종료면 살아 있는 셀이 더 많은 쪽이 이긴다.

| 조건 | 검사 시점 | 결과 |
| --- | --- | --- |
| 한쪽 셀 수 = 0 | 시뮬레이션 중 매 세대 직후 | 즉시 종료, 남은 쪽 승 |
| 양쪽 셀 수 = 0(같은 세대) | 위와 같음 | 즉시 종료, 무승부 |
| R번째 라운드의 시뮬레이션 완료 | 마지막 시뮬레이션 직후 | 셀 수가 많은 쪽 승, 같으면 무승부 |

- 배치·개입 단계에서는 전멸을 검사하지 않는다. 초기 배치 도중에는 한쪽이 0개일 수 있기 때문이다.
- **정체도 건너뛰지 않는다**: 보드가 정물이나 진동 상태가 돼도 시뮬레이션은 항상 K세대를 모두 진행한다. 주기 2 진동자 중에는 셀 수가 바뀌는 것이 있어서(beacon은 8개와 6개를 번갈아 가짐), 중간에 건너뛰면 개입 시작 보드와 최종 셀 수가 K세대를 다 돈 결과와 달라질 수 있다. K = 20이라 모두 진행해도 비용이 작다.
- 점수는 종료 시점의 셀 수만 본다. 누적 점수나 영역(칸) 점수는 채택하지 않았다. 상태 표시줄에는 현재 셀 수를 계속 보여준다.
- 채택하지 않은 대안: 정체 감지 후 남은 세대의 홀짝에 맞는 상태로 이동(결과는 같지만 감지·이동 로직과 테스트가 늘어남).

## 7. 예시 (시뮬레이터로 검증)

아래 5개 예시는 3장 규칙을 그대로 구현한 Python 시뮬레이터로 돌린 결과다. 보드 밖은 `DEAD`로 처리했고, 그대로 JUnit 특성 테스트의 기대값으로 쓸 수 있다. 격자에서 아래쪽 빈 행은 생략했다.

### 예시 1. 다수색 탄생 (5×5)

(2,1)의 이웃은 A 2개 + B 1개 = 3이라 A로 태어난다. B(3,1)은 이웃이 1개라 고립사한다.

```
세대 0 (A=2, B=1)    세대 1 (A=2, B=0)
.....                 .....
.A...                 .....
..A..                 .AA..
.B...                 .....
.....                 .....
```

### 예시 2. 상대 셀로 과밀사 시키기 (5×5)

가운데 A(2,2)는 이웃이 A 2개 + B 2개 = 4라 죽는다. B 두 개가 없었다면 이웃이 2개라 살아남았다. 동시에 (0,2)에는 이웃 A 2개 + B 1개로 A가 태어난다.

```
세대 0 (A=3, B=2)    세대 1 (A=3, B=1)
.....                 ..A..
.ABA.                 .ABA.
..A..                 .....
..B..                 .....
.....                 .....
```

### 예시 3. 영원히 끝나지 않는 보드 (6×10)

A의 blinker(주기 2)와 B의 block(정물)이 서로 닿지 않는다. 셀 수는 매 세대 A=3, B=4로 고정되고, 보드는 2세대마다 같아진다. 최대 라운드 제한이 없으면 끝나지 않고, 있으면 B가 4:3으로 이긴다. 정체 상태여도 세대를 건너뛰지 않고 K세대를 모두 진행한다(6장).

```
세대 0, 2, 4 …         세대 1, 3, 5 …
..........            ..........
..........            ..A.......
.AAA..BB..            ..A...BB..
......BB..            ..A...BB..
..........            ..........
```

### 예시 4. 동시 전멸 → 무승부 (10×10)

A의 glider가 B의 block에 부딪히면 양쪽이 같은 세대에 전멸한다. 셀 수는 세대 0~6에서 A=5, B=4로 유지되다가 세대 7에 6:5, 세대 8에 3:3, 세대 9에 1:2, 세대 10에 0:0이 된다. 6장 규칙에 따라 세대 10에서 무승부로 끝난다.

세대 7의 B(5,4)는 섞인 이웃(A 1개 + B 2개)에서 B로 태어난 셀이다. 충돌 지점에서 양쪽 모두 탄생으로 셀을 얻을 수 있음을 보여준다.

```
세대 0 (A=5, B=4)    세대 7 (A=6, B=5)    세대 9 (A=1, B=2)
.A........            ..........            ..........
..A.......            ..........            ..........
AAA.......            ..A.......            ..........
..........            ...AA.....            ...A......
..........            ..AAA.....            ..........
.....BB...            ....BBB...            .....B....
.....BB...            .....BB...            .....B....
..........            ..........            ..........
```

### 예시 5. 셀 1개 저격과 대응 (16×16)

A가 B의 block 옆면에 셀 1개를 두면, B가 대응하지 않을 때 양쪽 모두 4세대 뒤 0개가 된다(A 1개로 B 4개를 없앰다). B가 다음 차례에 셀 1개로 대응하는 경우를 주변 빈칸 67곳 전부에 대해 30세대씩 돌려 보면, 6곳에서 B가 4개 이상 살아남는다. 아래 (5,8) 대응은 A가 세대 8부터 0이 되고, B는 세대 10에 24가 된 뒤 40, 32, 40, 44, 56, 20을 거쳐 세대 17부터 B=24로 고정된다.

## 8. 미결 사항과 공통 인터페이스 요구사항

2인용 모드가 공통 구조에 요구하는 것은 아래 5가지다. 셀 상태와 이웃 조회(1~2번)는 Cell 리팩토링·암세포 모드와 회의에서 함께 확정해야 한다.

| # | 요구사항 | 쓰는 곳 |
| --- | --- | --- |
| 1 | 셀 상태를 boolean이 아닌 `DEAD` / `A` / `B`로 표현 | 3장 전이 규칙, 렌더러 색 매핑, 저장 |
| 2 | 이웃의 상태(종류)를 조회하는 메서드(`isAlive()` 대체) | 3장 다수색 탄생 |
| 3 | 상태별 셀 수 집계(`CountingVisitor` 재사용 후보) | 6장 승패 판정, 점수 표시 |
| 4 | 클릭 시 "현재 플레이어의 셀 배치"로 동작하는 입력 처리(`userClicked` 토글 대체) | 5장 배치 규칙 |
| 5 | 세대 수 카운트 | 4장 K세대 진행 |

1~2번의 제안: [../../docs/001-cell-state-representation.md](../../docs/001-cell-state-representation.md), [../../docs/interfaces.md](../../docs/interfaces.md)

결정 사항(11/02)과 남은 미결 사항

- 기본 수치: 설정값으로 빼고 기본값 N = 20, K = 20, M = 3, R = 5. 64×64 보드에서 진영 간 거리가 약 32칸이라 K = 10(라운드당 glider 이동 2.5칸)은 너무 짧음. 플레이 테스트 후 재조정
- 개입: 영역 제한 없음 + 1개씩 공개 교대 배치 + 패스 허용(연달아 두 번 패스하면 종료). 저격은 허용하되 마지막 수의 확정 저격을 패스 규칙으로 막음
- 저장·불러오기: 2인용 모드에서는 미지원, 저장 메뉴 비활성화. 색과 진행 상태(라운드·단계·차례·남은 개수)까지 별도 형식이 필요해 범위가 크고, "기존 기능 유지" 요구는 클래식 모드 대상이므로 충돌하지 않음. 시간이 남으면 게임 전체 저장을 Memento 확장으로 추가
- UI: 상태 표시줄 한 줄(단계, 현재 차례, 남은 배치 개수, A:B 셀 수) + 진영 경계선. 배치 가능 칸 강조는 범위 밖
- 배치 확정: 차례가 넘어가면 배치가 확정되고 취소할 수 없음(상대 대응 후 내 수를 바꾸는 것 방지)
- 정체 감지: 세대 건너뛰기 없음, 항상 K세대 진행(진동자 셀 수 변화로 결과가 달라지는 것 방지)
- 초기 배치 마지막 수: 경계 근처 저격 위험을 의도된 위험으로 둠(별도 제한 없음)

결정 사항(11/03)

- 개입 선공: 선공과 후공은 초기 배치부터 이어서 번갈아 간다. 라운드 1 개입 선공 = B
- 빈 확정: 임시 배치 없이 확정하면 거부한다
- 예시 5 정정: (5,8) 대응 시 B=24 고정은 세대 10이 아니라 세대 17부터
